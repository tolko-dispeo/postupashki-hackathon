# Архитектурные решения

## ADR-001: события являются неизменяемыми фактами

Статус: предложено.

Сырые события записываются как append-only. Исправления не переписывают историю незаметно.

## ADR-002: атрибуция отделена от оплат

Статус: предложено.

Одна оплата может получить несколько долей выручки в разных моделях. Поэтому модель и её результат нельзя хранить одним полем в `payment`.

## ADR-003: SQLite для демонстрации, PostgreSQL для развития

Статус: предложено.

Доступ к данным идёт через единый слой. Замена движка не меняет API и аналитические правила.

## ADR-004: реальные и синтетические данные маркируются

Статус: принято условиями кейса.

Каждый импорт и ключевой факт должен позволять отличить реальные данные от mock/synthetic.
