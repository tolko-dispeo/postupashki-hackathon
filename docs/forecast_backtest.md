# Forecast / backtest дневной выручки

Независимое дополнение к MVP: прогноз общей дневной выручки на 7 дней,
проверка на исторических периодах и сравнение с базовыми моделями.
Горизонт и минимальная длина обучения задаются параметрами. Прогнозирование
не меняет атрибуцию, API, дашборды, модели БД или контрольные CSV.

## Воспроизведение из чистой копии

Python 3.11+, из корня репозитория:

```powershell
python -m pip install -e ".[dev]"
python scripts/forecast_backtest.py --input data/mock/forecast/daily_revenue.csv --data-kind synthetic --output data/processed/forecast_demo
python -m pytest tests/test_forecasting.py tests/test_forecast_cli.py -q
```

Открыть `data/processed/forecast_demo/report.html` в браузере. HTML содержит
Plotly внутри файла и работает без CDN. Результаты не требуют notebook,
локального сервера, базы данных или файлов вне репозитория.

## Вход

CSV с колонками `date,revenue`: дата ISO и неотрицательная конечная сумма
выручки. Валюта должна быть единой для всего файла. Можно передать несколько
строк за день: они суммируются. Суммы передаются как числа с десятичной точкой.
Временные метки приводятся к UTC; для бизнес-дня в локальном часовом поясе
сначала агрегируйте данные в этом поясе и передайте календарные даты.

Пропуски дат по умолчанию вызывают ошибку: отсутствие выгрузки не считается
нулевыми продажами. Только если полнота наблюдений подтверждена, разрешён
`--fill-missing-zero`. Дни по краям ряда не достраиваются: вход должен включать
полный известный период, в том числе нулевые первый и последний дни.
Пустая история, NaN, бесконечности, отрицательная выручка и недостаточная длина
отклоняются. Возвраты требуют отдельного определения целевой метрики.

Для реальных данных подготовьте дневную выручку из `base.xlsx` или успешных
платежей (`succeeded`, amount > 0, paid_at заполнен) и запустите с
`--data-kind real`. Флаг указывает происхождение данных, а не проверяет его.
Не смешивайте real/synthetic. Личные идентификаторы прогнозу не нужны.
Результат на реальных продажах пока не заявляется: `base.xlsx` для этого
прогона отсутствовал. Пример в репозитории явно синтетический.

## Модели и разделение времени

- `last_value`: повторяет последнее наблюдение (простейший baseline).
- `weekly_naive`: повторяет последнюю неделю; для горизонта больше недели
  повторяет её циклически, не подставляя будущие факты.
- `weekday_mean`: среднее для соответствующего дня недели за последние
  28 доступных дней. Это кандидат для сравнения с baseline.

Алгоритм заранее фиксирует последние `horizon` дней как финальный holdout.
На более ранней истории строит непересекающиеся окна длиной `horizon`,
начиная после `min_train_days` (по умолчанию 14). Обучающая история расширяется.
Весь прогноз окна строится из одного момента времени до его начала.
Неполное окно validation не оценивается; его наблюдения доступны обучению
на последующих датах. Требуется минимум `min_train_days + 2 * horizon` дней.

Выбор модели: минимальный средний MAE всех validation-прогнозов, при равенстве
побеждает первая модель в списке выше. Holdout не участвует в выборе,
хотя результаты всех моделей на нём показаны для сравнения.
Выбранная модель затем обучается на всей истории для будущего прогноза.
Поэтому качество holdout оценивает ранее выбранную модель, а не победителя
задним числом на тесте. Если улучшения нет, оно не заявляется.

## Метрики и файлы

- MAE = mean(abs(prediction - actual)).
- RMSE = sqrt(mean((prediction - actual)^2)).
- WAPE = sum(abs(prediction - actual)) / sum(abs(actual)) * 100%.
  При нулевом знаменателе не определён, в JSON используется null.
- Bias = mean(prediction - actual), положительный означает завышение.
- Улучшение относительно weekly_naive = (MAE_baseline - MAE_model) /
  MAE_baseline * 100%. При нулевом MAE baseline не определено.

`predictions.csv` содержит phase, fold, model, origin, date, step, actual,
predicted. `metrics.csv` сравнивает модели по validation и holdout.
`forecast.csv` содержит будущие даты и прогноз выбранной модели.
`summary.json` фиксирует границы, параметры, происхождение и SHA-256 входа.
`report.html` объединяет график, таблицы и ограничения.

## Контрольный результат synthetic-примера

56 дней: 01.07.2026–25.08.2026. Пять validation-окон, финальный holdout
19.08–25.08. Модель: weekly_naive, holdout MAE = 525 денежных единиц,
прогноз на 26.08–01.09 суммарно 139 300. Улучшение относительно недельного
baseline равно 0%: именно baseline оказался лучшим по validation.

Данные примера не являются историческими продажами и не подтверждают качество
реального прогноза. Будущие бюджеты, цены и запуски не входят в модель.
Прогноз не оценивает causal effect и не обосновывает перераспределение бюджета.
Интервалы неопределённости не заявляются без проверки их покрытия.

## Дополнительный локальный прогон на расширенной базе

На полной локальной synthetic-БД `postupashki_mvp_large_demo.sqlite3` отдельно
проверен ряд сумм успешных оплат (`status=succeeded`, `amount>0`, непустой
`paid_at`, `is_synthetic=1`), сгруппированный по календарной дате paid_at.
Между 09.07 и 10.09.2026 получено 64 дня, включая два дня без успешных оплат,
явно заполненных нулями. Сумма ряда: 4 178 650 руб. База не входит в репозиторий.

Шесть validation-окон, holdout 04.09–10.09.2026. По validation выбрана
last_value: holdout MAE 52 507,14 руб., WAPE 69,80%. MAE weekly_naive
84 750 руб.; улучшение MAE составляет 38,04%. Ошибка остаётся высокой:
это свидетельство ограничения прогноза, а не доказательство его надёжности.
Прогноз 11.09–17.09 по модели на конец истории: 229 600 руб. за неделю.
Это historical-origin прогноз: более поздние факты не использованы.
Для воспроизведения без этой локальной БД используйте включённый пример выше.

## Проверки реализации

Тесты проверяют известные константный/недельный ряды, горизонт больше недели,
агрегацию строк, пропуски и некорректные значения, короткую историю, нулевую
выручку и непересечение окон. Изменение фактов финального holdout не должно
менять выбранную модель или прогнозы, построенные до этих фактов.

Дополнительно проверяется отсутствие утечки в каждом validation-окне,
метрики сверяются с ручным расчётом, RMSE не переполняется от возведения
больших конечных значений в квадрат. CLI-тесты создают весь комплект файлов,
проверяют хэш входа, повторяемость сводки, нулевую выручку и ошибочный CSV.

Отчёт содержит viewport для мобильных устройств, горизонтальную прокрутку
таблиц, адаптивные блоки и график с выделением holdout. В автоматической
проверке контролируется структура HTML и отсутствие внешнего script src.
Визуальная проверка в браузере этого запуска не завершена: политика браузера
заблокировала локальный file://. Это не заменяется заявлением о визуальном QA.
