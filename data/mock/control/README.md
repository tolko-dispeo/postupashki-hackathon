# Синтетический контрольный набор Contract v1

## Назначение

Набор фиксирует ожидаемую структуру событий и связи `placement → visit → lead → order → payment`. Он нужен для регрессионных тестов структуры данных, воронки, неполных сценариев и last-touch-атрибуции.

Все данные синтетические. Здесь нет настоящих имён, телефонов, Telegram ID или usernames. Набор маленький и не предназначен для массовой аналитики или демонстрации масштаба дашборда.

## Файлы

- `placements.csv` — пять размещений двух кампаний.
- `events.csv` — события четырёх сценариев в формате Contract v1.
- `tests/test_control_data.py` — проверки именно этих контрольных CSV.

Отметим что:

`scenario_id` файле в `events.csv`, является вспомогательным полем контрольного набора.

Оно:
- нужно только для разделения тестовых сценариев.
- не входит в обязательный конверт рабочего события.
- не обязано передаваться в POST /events.
- не хранится в текущей ORM-модели Event.

`campaign_name` в `placements.csv` продублирован только для удобства чтения. Каноническая связь выполняется по `campaign_id`, а в рабочей БД кампании и размещения находятся в отдельных таблицах.

## Сценарии

| Сценарий | Содержание | Ожидаемый результат |
|---|---|---|
| `scenario_01_full_funnel` | Один рекламный клик и полный путь до выдачи доступа | 1 лид, 1 заказ, 1 оплата на 42 900 ₽ |
| `scenario_02_multi_touch` | Один visitor сначала кликает `pl_001` кампании `cmp_autumn_26`, затем `pl_005` кампании `cmp_career_26` | 1 лид, 1 заказ, 1 оплата на 42 900 ₽; last-touch — `pl_005` |
| `scenario_03_lead_no_payment` | Посетитель доходит до менеджера, становится лидом и начинает диалог | 1 лид; заказа и оплаты нет |
| `scenario_04_view_no_lead` | Посетитель кликает рекламу, открывает сайт и смотрит курс | Лида, заказа и оплаты нет |

## Ожидаемая last-touch-атрибуция

Учитываются только `ad_click`, последнее касание до лида и окно 30 дней.

| Оплата | Сумма | Placement | Кампания | Причина |
|---|---:|---|---|---|
| `payment_control_001` | 42 900 ₽ | `pl_002` | `cmp_autumn_26` | Единственный подходящий клик |
| `payment_control_002` | 42 900 ₽ | `pl_005` | `cmp_career_26` | Последний из двух кликов до лида; `pl_001` оплату не получает |

Если подходящего `ad_click` за 30 дней до лида нет, оплата остаётся `unattributed`.

## Проверка

Из корня проекта:

```bash
pytest tests/test_control_data.py
```

Тест проверяет обязательные столбцы, уникальность ID, допустимые события, placement-ссылки, JSON в `properties`, хронологию, дополнительные ID, оплаты, контрольные количества, выручку и `is_synthetic`.
