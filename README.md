# Поступашки — Marketing Measurement MVP

Каркас системы, которая должна сделать измеримым путь:

`размещение рекламы → переход → действие на сайте → обращение к менеджеру → заказ → оплата`.

Сейчас это работающий end-to-end MVP на синтетических данных: tracking-ссылка фиксирует рекламный клик, события сайта связываются с лидом, заказом и оплатой, last-touch атрибуция относит выручку к размещению, а Streamlit-дашборд показывает воронку и сравнение кампаний.

## Что входит в первую версию MVP

1. Реестр кампаний и рекламных размещений.
2. Генерация уникальной tracking-ссылки для `placement_id`.
3. Приём событий клика и действий на сайте.
4. Связывание анонимного посетителя с лидом через идентификатор в ссылке/заготовленном сообщении менеджеру.
5. Загрузка заказов и оплат.
6. Last-touch атрибуция.
7. Расчёт воронки и `ROMI_attr`.
8. Дашборд на синтетических данных.

Исторический `base.xlsx` анализируется отдельно в ноутбуке: он описывает продажи, но не содержит касаний и поэтому не используется для доказательства эффективности каналов.

## Что добавляется позже без смены ядра

- Telegram collector и автоматическое обнаружение постов;
- NLP-классификация постов;
- другие модели атрибуции;
- эксперименты и incremental ROMI;
- прогнозирование и рекомендации по бюджету;
- PostgreSQL вместо SQLite;
- Superset вместо или вместе со Streamlit.

Эти компоненты подключаются новыми таблицами, сервисами и миграциями. Основные сущности `campaign`, `placement`, `event`, `lead`, `order`, `payment` сохраняются.

```text

```

## Быстрый запуск

Требуется Python 3.11+.

```powershell
python -m pip install -e ".[dev]"
python scripts/init_db.py
python scripts/seed_demo.py
uvicorn postupashki_mvp.api:app --reload
```

Проверка API: `http://127.0.0.1:8000/health`.

Дашборд:

```powershell
streamlit run src/postupashki_mvp/dashboard/app.py
```

Синтетический сценарий создаёт 3 кампании и 6 размещений с разными расходами, конверсиями и ценами продуктов. В дашборде можно выбрать одну кампанию, изучить её воронку и сравнить кампании по выручке, расходам, CAC и ROMI. Один тестовый посетитель касается двух кампаний; его оплата атрибутируется только последнему касанию.

Тесты:

```powershell
pytest
```

## Порядок дальнейшей разработки

1. Выделить кампанию и креатив в отдельные сущности реестра рекламы.

3. Добавить контроль качества stitching и долю неатрибутированной выручки.

5. Добавить сценарий распределения следующего рекламного бюджета.

## Правила данных

- Реальные и синтетические данные нельзя смешивать без признака `is_synthetic`.
- Сырые события не перезаписываются; исправления делаются отдельными записями или миграциями.
- Telegram ID, телефон и username не хранятся в аналитическом слое открытым текстом.
- Метод и версия атрибуции всегда фиксируются вместе с результатом.
- Схема БД меняется только через версионируемые миграции.
